## Session Focus: Next.js security patch (15.3.3 → 15.5.29)

`next@15.3.3` carried three critical remote-code-execution advisories, fixed in
15.5.24 and 15.5.28. This session moves `next` and `eslint-config-next` to
15.5.29, the newest 15.x release, with no application code changes.

## What changed

- `next` 15.3.3 → 15.5.29, `eslint-config-next` 15.3.3 → 15.5.29 (both pinned).
- `yarn.lock`: only Next's own dependency tree moved: its SWC binaries,
  `sharp` 0.34.2 → 0.35.5 (the optional image optimiser), and `busboy` /
  `@swc/counter` dropped. No other app dependency changed version.

## Found while verifying (pre-existing, not caused by this bump)

- **`middleware.ts` has never been compiled.** It sits at the repository root,
  but the app lives under `src/app`, and Next only picks up middleware next to
  the `app` directory (`src/middleware.ts`). Both builds leave
  `middleware-manifest.json` empty, and `/api/accounts` answers with the route
  handler's own 401 rather than the `withAuth` redirect. Moving the file to
  `src/middleware.ts` in a throwaway copy of master made the build print
  `ƒ Middleware 60.1 kB` with matchers `/accounts/:path*` and
  `/api/accounts/:path*`. Every API route handler checks the session itself
  and returns 401 (all six non-auth handlers, checked by reading them and by
  the requests above), so the API is not open because of this; the pages
  under `/accounts` were not each audited. The file reads as protection that
  is not there. The dev server's `✓ Compiled middleware` line
  appears even so and proves nothing.
- **`/transactions` returns 500 for a signed-out visitor.**
  `src/app/transactions/page.tsx` calls `forbidden()` from `next/navigation`,
  which throws unless `experimental.authInterrupts` is set in `next.config.ts`,
  and it is not. Same error on 15.3.3 and 15.5.29.
- **The first transaction wipes an account's starting balance.**
  `recomputeAccountBalance()` in `src/lib/transactions/balance.ts` sets the
  balance to income minus expenses over the account's transactions, so the
  initial balance typed into the new-account form is lost: an account created
  with €100 showed -€20 after one €20 expense (`GET /api/accounts` returned
  `"balance": -20`). Because cash accounts reject negative balances, the edit
  form then refused to save even a rename until the balance field was changed
  by hand.
- **Dashboard widgets go stale after a create.** The account and transaction
  widgets are server components; the forms only update the React Query cache,
  so the dashboard kept showing €100 and "No transactions yet" until a reload.
  The new-account form also only calls `form.reset()` on success, so its modal
  stays open; the other three modals close themselves.
- **The edit-transaction form stores "Other" for a blank category.** A
  transaction created without a category came back with `"category":
"Other"` after an edit that did not touch the field.
- **Worktree builds warn about the workspace root.** In a git worktree under
  `.claude/worktrees/`, Next finds the main checkout's `yarn.lock` above the
  worktree and infers that as the root. Build and dev still succeed. Not
  checked in a plain checkout.

## Learned

- **`next lint` is deprecated in 15.5 and removed in Next.js 16.** The build
  and `yarn lint` now print the warning. Before any move to 16, the `lint` and
  `lint:fix` scripts need to call ESLint directly (`eslint .`, with the flat
  config already in `eslint.config.mjs`).
- **Building in a sandbox without Google Fonts or Prisma's binary host:**
  `next/font/google` fails the build when `fonts.googleapis.com` is
  unreachable; Next reads `NEXT_FONT_GOOGLE_MOCKED_RESPONSES` (a path to a JS
  module mapping each CSS URL to CSS text) and skips the fetch. `prisma
generate` needs `binaries.prisma.sh`; `prisma generate --no-engine` with
  `PRISMA_SCHEMA_ENGINE_BINARY` and `PRISMA_QUERY_ENGINE_LIBRARY` pointed at
  empty stub files produces the client types without downloading. Both are
  build-check workarounds only; a client generated with `--no-engine` cannot
  query a database.

## Still open (not part of this change)

- `next-auth@4.24.11` has advisories fixed in 4.24.15. The critical one
  (email homoglyph bypass) needs the Email provider, which this app does not
  use (Google only). Two still apply in principle: `getToken()` throwing on a
  malformed `Authorization: Bearer` header and OAuth check cookies not bound
  to their provider. The `getToken()` path was thought to be reached through
  `withAuth` in `middleware.ts`, but that middleware is never compiled (see
  above), so it is reachable only if the middleware is moved under `src/`. A
  bump within the existing `^4.24.11` range covers both.
- The remaining `yarn audit` entries are dev and build tooling (ESLint's
  minimatch / brace-expansion, `tar` under Prisma's tooling, Next's own
  pinned `postcss@8.4.31`), not code that runs on a user request.

## Session Focus: keep an account's opening balance

### What changed (opening balance)

- New column `FinancialAccount.openingBalance` (migration
  `20261110112920_add_account_opening_balance`), backfilled as
  `balance − (Σ income − Σ expense)` per account.
- `recomputeAccountBalance()` now sets `balance = openingBalance + net`
  instead of `net`, so the first transaction no longer wipes the starting
  balance (before: €100 cash account + €20 expense showed −20).
- Creating an account stores the typed balance as `openingBalance` too;
  editing "Current Balance" derives `openingBalance` from it. The edit form
  sends `balance` only when that field changed, so a rename never resets it.
- The account row is locked (`SELECT … FOR NO KEY UPDATE`) before any write that
  derives one column from the transaction sums, so a concurrent transaction
  write and balance edit cannot leave them out of step.
- The 7-day balance chart starts from `openingBalance`.

Spec: `docs/superpowers/specs/2026-11-10-account-opening-balance-design.md`.

### Risks / follow-ups (opening balance)

Accounts whose starting balance the bug already overwrote get
`openingBalance = 0`; the owner fixes them by setting Current Balance once.
Other follow-ups are in `docs/parking-lot.md`.
